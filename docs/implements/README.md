# Implementation notes

## Purpose

Reserved for implementation notes tied to a concrete delivery that do not belong in an ADR or permanent API contract.

## Responsibilities

Provides short-lived or feature-specific technical context with a clear owner and removal plan.

## What belongs here

- Implementation checklists.
- Migration or rollout notes.
- Technical handoff notes.

## What does not belong here

- Permanent architecture decisions; use `docs/adr`.
- Product requirements; use `docs/design`.
- Secrets or local environment files.
